# Test utilities

`ast-predicate/test-utils` contains optional helpers for testing SQL generated by predicate adapters or services.

The package does not depend on Jest or Vitest directly. Instead, pass the `expect` function from your test framework.

```ts
import { createCompiledSqlExpect } from 'ast-predicate/test-utils';

const {
    expectCompiledSql,
    expectSelectFrom,
    expectUpdateTable,
    expectWhereEquals,
    expectWhereIsNull,
    expectNoWhereEquals,
    expectSetColumn,
    expectOrderByColumn,
    expectLimitParameter,
    expectParameterOccurrences,
} = createCompiledSqlExpect(expect);
```

## Basic SQL assertion

```ts
expectCompiledSql(
    {
        sql: `
            select *
            from "superlicensor"."Editions"
            where "TenantCode" = $1
              and "deletedAt" is null
            limit $2
        `,
        parameters: ['tenant-1', 25],
    },
    {
        contains: ['from "superlicensor"."Editions"'],
        matches: [/"TenantCode"\s*=\s*\$\d+/i],
        parameters: ['tenant-1'],
        exactParameters: ['tenant-1', 25],
    },
);
```

## PostgreSQL query helpers

```ts
const compiled = {
    sql: `
        select *
        from "superlicensor"."Editions"
        where "TenantCode" = $1
          and "ProductCode" = $2
          and "deletedAt" is null
        order by "name" asc
        limit $3
    `,
    parameters: ['tenant-1', 'product-1', 25],
};

expectSelectFrom(compiled, 'superlicensor.Editions');
expectWhereEquals(compiled, 'TenantCode', 'tenant-1');
expectWhereEquals(compiled, 'ProductCode', 'product-1');
expectWhereIsNull(compiled, 'deletedAt');
expectOrderByColumn(compiled, 'name', 'asc');
expectLimitParameter(compiled, 25);
expectParameterOccurrences(compiled, 'tenant-1', 1);
```

## Update query helpers

```ts
const compiled = {
    sql: `
        update "superlicensor"."Editions"
        set "description" = $1
        where "code" = $2
    `,
    parameters: ['Updated description', 'edition-1'],
};

expectUpdateTable(compiled, 'superlicensor.Editions');
expectSetColumn(compiled, 'description', 'Updated description');
expectWhereEquals(compiled, 'code', 'edition-1');
```

## Available helpers

```ts
createCompiledSqlExpect(expect)
normalizeSql(sql)
quotedPgTable(table)
quotedPgColumn(column)
```

The object returned from `createCompiledSqlExpect(expect)` contains:

```ts
expectCompiledSql(compiled, assertion)
expectSelectFrom(compiled, table)
expectUpdateTable(compiled, table)
expectWhereEquals(compiled, column, value?)
expectWhereIsNull(compiled, column)
expectNoWhereEquals(compiled, column, value?)
expectSetColumn(compiled, column, value?)
expectOrderByColumn(compiled, column, direction)
expectLimitParameter(compiled, limit)
expectParameterOccurrences(compiled, value, count)
```

## PostgreSQL assumptions

The current SQL helpers are PostgreSQL-oriented. They assume double-quoted identifiers such as `"TenantCode"` and positional parameters such as `$1`, `$2`, and `$3`.

This makes them suitable for Kysely/PostgreSQL adapter tests and similar service-level tests, but they are not intended to be database-neutral SQL assertions.
